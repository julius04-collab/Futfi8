# Accessibility (a11y) Conventions

## Minimum Compliance Level

Target: **WCAG 2.1 Level AA** for all user-facing pages.

These rules are a starting point — they prevent the most common failures
without requiring exhaustive audits. Post-MVP, run a full axe DevTools
scan and fix any AA violations.

## Keyboard Navigation

### Focusable Elements
- Every interactive element (button, link, input) must be focusable via keyboard
- Never use `<div onClick={...}>` without `role="button"` and `tabIndex={0}`
- Custom components use native HTML elements where possible: `<button>` not `<div onClick>`

```tsx
// Good — native button, focusable by default
<button onClick={handleSubmit} disabled={isSubmitting}>
  Post Take
</button>

// Bad — div with click handler, not focusable
<div onClick={handleSubmit}>Post Take</div>

// Acceptable — div with proper ARIA (use sparingly)
<div role="button" tabIndex={0} onClick={handleSubmit} onKeyDown={handleKeyDown}>
  Post Take
</div>
```

### Focus Order
- Tab order follows visual order — never use positive `tabIndex` values
- Modals trap focus: Tab cycles within the modal, closes on Escape
- Bottom nav items are navigable via Tab
- Post cards skip to "Upvote" as the first interactive element

### Visible Focus Indicators
- Never remove `outline` without providing a custom focus style
- All interactive elements have a visible focus ring:
```css
/* Default focus style — defined in global CSS */
:focus-visible {
  outline: 2px solid #9B6EFF;
  outline-offset: 2px;
}
```

```tsx
// Button with Tailwind focus ring
<button className="focus-visible:ring-2 focus-visible:ring-purple-electric focus-visible:ring-offset-2 focus-visible:outline-none">
  Post Take
</button>
```

## ARIA Labels

### Required Labels

| Element | ARIA Attribute | Example |
|---|---|---|
| Icon-only button | `aria-label` | `<button aria-label="Upvote post">▲</button>` |
| Navigation landmark | `aria-label` | `<nav aria-label="Main navigation">` |
| Search input | `aria-label` | `<input aria-label="Search clubs" />` |
| Loading state | `aria-label` or `aria-busy` | `<div aria-busy="true">Loading...</div>` |
| Error message | `role="alert"` | `<div role="alert">Post failed.</div>` |
| Live region | `aria-live` | `<div aria-live="polite">New post received.</div>` |
| Tab panel | `role="tabpanel"` | `<div role="tabpanel" aria-labelledby="tab-feed">` |

### Dynamic Content

```tsx
// Toast notifications — announced by screen readers
<div role="status" aria-live="polite" aria-atomic="true">
  {toast.message}
</div>

// Unread notification badge
<span aria-label={`${unreadCount} unread notifications`}>
  {unreadCount > 99 ? '99+' : unreadCount}
</span>

// Loading skeleton
<div aria-label="Loading posts" aria-busy="true">
  <PostSkeleton />
</div>
```

## Images & Icons

### Images
- Every `<Image>` has a descriptive `alt` attribute
- Decorative images (backgrounds, spacers) use `alt=""`
- Club crests: `alt="${club.name} crest"`
- User avatars: `alt="${username}'s avatar"`
- Default/fallback avatars: `alt=""` (decorative)

```tsx
// Good
<Image src={crestUrl} alt={`${club.name} crest`} width={32} height={32} />

// Decorative
<Image src="/bg-pattern.svg" alt="" role="presentation" />
```

### Icons
- Icons without text labels need `aria-hidden="true"` and an `aria-label` on the parent button
- Icons with adjacent text labels can use `aria-hidden="true"` (the text serves as the label)

```tsx
// Icon-only button
<button aria-label="Close modal">
  <XIcon aria-hidden="true" />
</button>

// Icon + text
<button>
  <HeartIcon aria-hidden="true" />
  <span>Like</span>
</button>
```

## Color & Contrast

### Minimum Contrast Ratios
- Normal text (<18px): **4.5:1** against background
- Large text (≥18px bold or ≥24px): **3:1**
- UI components (borders, icons): **3:1**

### Current Token Compliance

| Token | Hex | On `#0D0D0F` (pitch) | Ratio |
|---|---|---|---|
| `text-white` | #FFFFFF | ✓ | 19.6:1 |
| `text-secondary` | #CCCCCC | ✓ | 10.8:1 |
| `text-muted` | #888888 | ✓ | 5.3:1 |
| `text-accent` | #9B6EFF | ✓ | 6.2:1 |

All approved text tokens pass AA on `bg-pitch` and `bg-midnight`.

### Color-Only Information
- Never convey information through color alone
- Badge levels: emoji + text label, not just color
- Match outcomes: text label ("Won", "Lost", "Draw"), not just green/red
- Raid status: icon + text, not just purple background

```tsx
// Good — icon + text + color
<span className="text-win">
  <CheckIcon aria-hidden="true" />
  <span>Won</span>
</span>

// Bad — color only
<span className="text-win">Won</span>
```

## Screen Reader Announcements

### Live Regions for Dynamic Content

```tsx
// New post appears in feed
<div aria-live="polite" aria-atomic="false" className="sr-only">
  New post from {username}
</div>

// Raid starts
<div role="status" aria-live="assertive">
  Arsenal raid has started. 2 hours remaining.
</div>

// Error state
<div role="alert">
  Failed to post your take. Check your connection.
</div>
```

### Screen Reader-Only Text

```css
/* Utility class for screen-reader-only content */
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border-width: 0;
}
```

Use for additional context that sighted users don't need:
```tsx
<time dateTime={post.created_at}>
  <span className="sr-only">Posted </span>
  {formatRelativeTime(post.created_at)}
</time>
```

## Focus Management

### Post-Interaction Focus
- After submitting a post: focus returns to the composer input
- After closing a modal: focus returns to the element that triggered it
- After navigating tabs: focus moves to the active tab panel
- After upvoting: focus stays on the upvote button

### Modals & Sheets
```tsx
// Modal focus management
useEffect(() => {
  if (isOpen) {
    // Save previously focused element
    previousFocus.current = document.activeElement as HTMLElement
    // Move focus to modal title
    modalTitleRef.current?.focus()
  } else if (previousFocus.current) {
    // Restore focus on close
    previousFocus.current.focus()
    previousFocus.current = null
  }
}, [isOpen])
```

## Touch Targets

- Minimum touch target size: **44×44px** (WCAG 2.2)
- Applies to all interactive elements on mobile
- Bottom nav items, upvote buttons, tab buttons, post composer submit

```tsx
// Good — 44px minimum height
<button className="min-h-[44px] min-w-[44px] flex items-center justify-center">
  <Icon />
</button>
```

## A11y Rules

1. Every interactive element is keyboard-focusable — never `onClick` on a `<div>` without proper ARIA
2. Every image has an `alt` attribute — decorative images use `alt=""`
3. Color is never the sole indicator of state, status, or importance
4. All text on dark backgrounds meets 4.5:1 contrast minimum
5. Icon-only buttons have `aria-label` — icons themselves use `aria-hidden="true"`
6. Modals trap focus and restore it on close
7. Dynamic content uses `aria-live` regions for screen reader announcements
8. Touch targets are minimum 44×44px on mobile
9. Focus indicators are visible — never `outline: none` without replacement
10. `sr-only` class used for content that is visually hidden but needed by screen readers
